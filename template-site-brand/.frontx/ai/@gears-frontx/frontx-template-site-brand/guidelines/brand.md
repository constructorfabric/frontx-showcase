# template-site-brand: the brand guideline

How the FrontX site's brand sits on top of `@gears-frontx/ui-kit`, where each value comes from, and how to change one. Read it before touching a colour, a type size or a font anywhere in the site.

## Layers

1. The kit's `theme.css`: every token the kit components read, in a light and a dark palette.
2. This brand, `@gears-frontx/site-brand`: brand values on kit tokens (light only) and the brand tokens the kit lacks (`--site-*` text shades, display type, weights, tracking, radii, motifs), all from one record, `src/brand.json`.
3. Art palettes local to an art component (the hairline figures, the hero and map drawings): hex values declared at the top of the art module, nowhere else.

Nothing else declares a colour. Blocks and screens read tokens with `var(--name)`; a hex literal outside `brand.json`, an art palette or a mask stop is a defect.

## Where the files are

- `src/brand.json`: the single source. Each row: token, our value, the V2 design value, the reason for any difference, the role. A row with value `null` records a V2 value the site does not adopt.
- `src/tokens.css` and `src/theme.ts`: generated by `npm run brand:generate`; never edit them. `tokens.css` declares the light values under `:root:not([data-theme='dark']), [data-theme='light']:not([data-theme='dark'])`, which outranks the kit light block on every light scope, the brand token resets on every `[data-theme='dark']` scope, and the theme-invariant tokens on `:root`. `theme.ts` holds the complete light and dark variable sets (kit palette plus brand overrides) shaped for the theme registry.
- `src/font.css`: the variable Inter (`@fontsource-variable/inter`, weights 100 to 900, latin and latin-ext) under the family name `Inter`, which the kit's `--font-sans` and `--font-heading` already name.
- `src/document.css`: the document entry, importing tokens and font. The page layout tokens are not brand values: the site-blocks package declares them in its own document entry. The shell loads every template package's `src/document.css` in the document after the kit's `theme.css`; the head-style adoption carries the document's sheets into every screen's shadow root, so no screen imports the brand.
- `src/assets/`: brand images used inside pages, imported as modules (`@gears-frontx/site-brand/assets/constructor-weave.svg`, the lockup logo). Head assets (favicons, the share image) belong to the project root.

## Brand art

`src/art/` holds the drawings blocks place in their content slots, one entry each (`@gears-frontx/site-brand/art/<Name>`): `HairlineFigure`, `TemplateFigure`, `HeroArt`, `ClosingVisual`, `ArchitectureFigure`, `WorkbenchFigure`, `ChartThumb`, `MetricBars`. The site draws them itself with the structure of V2's figures; V2's figure script and image assets are never copied. Rules for a drawing:

- It fills its slot's width and has no outer margin or position; the block decides the slot's size.
- Its palette is the first rule (or rules) of its stylesheet, custom properties only; a dark palette, where the drawing follows the page's theme, switches every colour of the light one. Hex and `rgb()` values appear nowhere else in the art (`src/art/palettes.test.ts`).
- It is hidden from assistive technology unless it takes a `label`; a drawing with links or text (the architecture figure, the workbench) renders them as real links and text.
- Hover motion runs only without the reduced-motion preference.

## Deliberate differences from V2

Each one is a row in `brand.json` with its reason; the table below repeats them. In short: the label lilac `#6c6aa9` instead of `#7775bb` (4.5:1 instead of 3.81:1 on the pale band); the hover of the brand blue derived with `color-mix` instead of the kit's shade; the deeper accent ink `#0546cc`; the dark theme keeps the kit's dark palette with brand text resets, since V2 has no dark site theme; V2's secondary and chart recolouring is recorded but not adopted; the font family is `Inter` (V2 names it `FrontXInter`, latin only), so the kit tokens resolve without an override.

## How to add or change a value

1. A kit token that carries the role exists: use it, no brand row.
2. The brand wants another value for a kit token: add or change a row in `light.overrides`.
3. The kit has no token for the role: add a brand token row (`--site-*`) and record the kit gap in the project's gap list.

Then measure the V2 value and write it in the row (or `null` when V2 has none, with a reason), run `npm run brand:generate`, and run `npm run brand:check`. Values follow the design guardrails' create-theme rules: a full CSS colour, no colour fragments, hover tokens derived from their base with `color-mix(in oklab, var(--base) N%, ...)`, alpha through `color-mix(..., transparent)`, no token re-wrapped in a colour function.

## What `brand:check` holds

1. `tokens.css`, `theme.ts` and the table below equal what `brand.json` generates.
2. Every override names a token the installed kit declares; no brand token takes a kit name.
3. The create-theme value rules, and each palette declares its appearance.
4. Every recorded background and text pair keeps 4.5:1, light against the kit light palette with the brand applied, dark against the kit dark palette with the resets.
5. Every row records its V2 value, and a difference carries a reason.
6. Every brand token is read somewhere in the project.
7. No file outside this package declares a brand token or a kit token the brand overrides.
8. The site config's `themeColor` and `backgroundColor` equal the brand record.

## The host theme stamp

Screens re-declare the kit palette on their shadow host from `:host(...)` rules, and the kit's OS-dark fallback follows the operating system, not the site. The shell stamps the site's appearance on every screen's shadow host so the document's light or dark block (kit and brand) matches the host from the outer tree and wins. The stamp lives in the shell; it goes away when the MFE runtime stamps the appearance itself, and then the light overrides move into the light theme's variables from `@gears-frontx/site-brand/theme`, leaving `tokens.css` with the brand tokens only.
