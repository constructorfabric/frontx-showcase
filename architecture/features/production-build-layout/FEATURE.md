## 1. Feature Context

- [x] `p2` - `cpt-site-feature-production-build-layout`

### 1.1 Overview

The production build is one static folder, `site/dist/`, that holds the host document, the manifest aggregate, every remote under `mfe/<package>/` and the generated metadata outputs. After the host build, `npm run site:dist` copies every remote the aggregate names into that folder and rewrites each remote's `publicPath` relative to the aggregate; at run time the host's registration bootstrap fetches the aggregate from the build base resolved against the document, and the MFE handler of `@gears-frontx/mfes` resolves each relative `publicPath` against the document, which sits in the same folder as the aggregate, so the same folder works at the root of an origin and under any sub-path. The bootstrap's screen domain mount handler also reports a failed load or mount to the shell layout's failure store.

### 1.2 Purpose

Hosting is not chosen yet, and the shell's build fetches the aggregate from a fixed place while its generator writes absolute remote addresses; the site must be publishable anywhere without a rebuild. The build sequence (`npm run build`: compose, the shell build, `site:dist`, then the metadata outputs generated by template-site-meta's command line from `site.config.json`, the screens' `seo` blocks and the raster record `assets/rasters.json` of `assets/og-image.svg`) is declared in the root `package.json`, which carries no markers; the generator, its outputs and the metadata check are specified in [template-site-meta DESIGN](../../../template-site-meta/architecture/DESIGN.md). The root's share of the metadata requirements is the site-level values declared once in `site.config.json` and the build step that derives every output from them. The relative build base itself is set in `site/vite.config.ts`, a configuration file the registry ignores.

**Requirements**: `cpt-site-fr-static-build`, `cpt-site-fr-metadata-single-source`, `cpt-site-fr-discovery-files`

**Principles**: `cpt-site-principle-metadata-once`

## 2. Actor Flows (CDSL)

### Lay out the production build

- [x] `p2` - **ID**: `cpt-site-flow-production-build-layout-lay-out-dist`

**Actor**: `cpt-site-actor-site-developer`

**Use case**: `cpt-site-usecase-change-screen`

**Success Scenarios**:
- After the host build, every remote of the aggregate sits in `site/dist/mfe/<package>/` without the files the host never reads, every `publicPath` in the aggregate reads `mfe/<package>/`, and the command names the packages it laid out.

**Error Scenarios**:
- `site/dist/` holds no aggregate: the command refuses before it writes, naming the missing file.
- The aggregate names a manifest no built package carries: the command refuses before it writes, naming the manifest.

**Steps**:
1. [x] - `p2` - The developer runs `npm run site:dist` (or `npm run build`, which runs it after the host build); the command lays out the site directory of the repository - `inst-run-layout`
2. [x] - `p2` - **IF** `site/dist/` has no manifest aggregate, refuse before writing anything - `inst-if-no-aggregate`
3. [x] - `p2` - Read the aggregate's configs and index the built packages under `site/src-app/mfe_packages/` by the manifest id their build's enriched manifest carries, skipping the shared folder and dot entries - `inst-index-built`
4. [x] - `p2` - **FOR EACH** aggregate config, find its package; **IF** no built package carries its manifest id, refuse before writing anything - `inst-if-unknown-manifest`
5. [x] - `p2` - Remove any previous `dist/mfe/` layout, so the result replaces rather than merges - `inst-clear-layout`
6. [x] - `p2` - **FOR EACH** laid-out package, copy its build into `dist/mfe/<package>/` without the preview page, the federation types, the build statistics and the enriched manifest, and set the `publicPath` of its manifest and of every entry's manifest to `mfe/<package>/` - `inst-copy-and-rewrite`
7. [x] - `p2` - Write the aggregate back and **RETURN** the package directories in aggregate order - `inst-write-aggregate`
8. [x] - `p2` - Print the laid-out packages; **IF** the layout refused, print its message and exit with a failure - `inst-report`

### Load the screens at any mount point

- [x] `p2` - **ID**: `cpt-site-flow-production-build-layout-load-screens`

**Actor**: `cpt-site-actor-visitor`

**Use case**: `cpt-site-usecase-visit-page`

**Success Scenarios**:
- The visitor opens the built site at the root of an origin or under a sub-path; the host reads its own copy of the aggregate next to the document, registers every package with the remote addresses the aggregate writes and mounts the screens the address names.

**Error Scenarios**:
- The aggregate does not answer: bootstrap fails with the address and status, and the shell layout shows its bootstrap failure state.
- The aggregate is empty: bootstrap warns and registers no package.

**Steps**:
1. [x] - `p2` - **IF** the app has no MFE registry, fail the bootstrap - `inst-if-no-registry`
2. [x] - `p2` - Register the host chrome action schemas on the registry's type system - `inst-register-chrome-schemas`
3. [x] - `p2` - Register the screen domain, opted into the two chrome actions and built with the failure-reporting mount handler, and the sidebar, popup and overlay domains - `inst-register-domains`
4. [x] - `p2` - Broadcast the current theme and language as shared properties - `inst-broadcast-properties`
5. [x] - `p2` - Resolve the aggregate's address from the build base against the document's address - `inst-resolve-aggregate-url`
6. [x] - `p2` - Fetch the aggregate; **IF** it does not answer successfully, fail the bootstrap naming the address and status - `inst-fetch-aggregate`
7. [x] - `p2` - **IF** the aggregate lists no package, warn and **RETURN** - `inst-if-empty`
8. [x] - `p2` - Register every package's non-action schemas first, so a leaf package's extensions validate through schemas a parent package declares whatever the aggregate's order - `inst-register-non-action-schemas`
9. [x] - `p2` - **FOR EACH** package, register its declared action schemas, its manifest, its domains, its entries and the extensions of domains the host owns, putting an extension of a domain another runtime owns only on the type system - `inst-register-packages`
   1. [x] - `p2` - Register the package's schemas whose id is an action its entries declare (a screen's show action among them) - `inst-register-action-schemas`
   2. [x] - `p2` - Register the package's manifest, its domains and its entries on the type system - `inst-register-declarations`
   3. [x] - `p2` - Register each extension of a domain the host owns with the registry, and put an extension of a domain another runtime owns only on the type system, which every runtime of the page shares - `inst-register-extensions`

### Serve the build from Node

- [x] `p2` - **ID**: `cpt-site-flow-production-build-layout-serve-dist`

**Actor**: `cpt-site-actor-site-developer`

**Use case**: `cpt-site-usecase-change-screen`

**Success Scenarios**:
- The developer, or a Node host such as DigitalOcean App Platform, runs `npm start` after `npm run build`; `site/dist/` answers on `PORT` (8080 by default) with the headers, cache policy and content types of the image's server (`deploy/site/Caddyfile`).

**Error Scenarios**:
- `site/dist/index.html` is missing: the command exits with a failure that names `npm run build`.
- `PORT` is not an integer from 0 to 65535, or the address cannot be listened on (already in use, for one): the command prints one line naming the problem, the host and port where it applies, and exits with a failure.
- A request names no file under `site/dist/`: dot segments are resolved inside the build root, so a path can never leave `site/dist/`, and the answer is `404 Not Found` as plain text that is never cached.
- A file cannot be opened: the answer is `500 Internal Server Error` as plain text that is never cached, and the failure is logged with the file and the reason.

**Steps**:
1. [x] - `p2` - **IF** `site/dist/index.html` is missing, exit with a failure that names `npm run build` - `inst-if-no-build`
2. [x] - `p2` - Listen on `SERVE_HOST` (`0.0.0.0` by default; not `HOST`, which shells set to the hostname) and `PORT` (8080 by default) and print the address with the port bound, which `PORT=0` leaves to the system, keeping an idle connection open for 65 seconds (headers allowed 66, a socket that moves no bytes for 120 seconds closed), longer than a platform load balancer keeps its upstream sockets; **IF** `PORT` is not an integer from 0 to 65535 or the listen fails, print one line and exit with a failure - `inst-listen`
3. [x] - `p2` - **IF** the method is not GET or HEAD, answer 405 - `inst-if-method`
4. [x] - `p2` - Decode the path without its query string; **IF** it does not decode, carries a NUL byte, it names nothing; otherwise resolve its dot segments inside `site/dist/`, so it never leaves it - `inst-resolve-path`
5. [x] - `p2` - **IF** the path names a folder, serve its `index.html` without a redirect; **IF** it names nothing, or a file whose real path, links followed, lies outside `site/dist/`, answer 404; open the file before any header goes out and read everything after from that handle, its size and time from the handle's own stat; **IF** it cannot be opened, answer 500 - `inst-folder-index`
6. [x] - `p2` - Set the security headers, `Cache-Control` immutable for a file under the host's or a remote's `assets/` folder of the resolved path (`/assets/`, `/mfe/<package>/assets/`) and `no-cache` elsewhere, the content type by extension (`*.md` as `text/plain; charset=utf-8`, `*.webmanifest` as `application/manifest+json`), and the validators, one strong `ETag` per file from its size and time - `inst-headers`
7. [x] - `p2` - **IF** the request's `If-None-Match` is `*` or lists the file's tag, compared weakly, or, with no `If-None-Match`, its `If-Modified-Since` is a date at or after the file's time in whole seconds, answer 304 with the same headers - `inst-if-unchanged`
8. [x] - `p2` - Send the file as it is, uncompressed whatever `Accept-Encoding` asks (a CDN or proxy in front compresses), with its length: stream exactly the size the file was found with from the open handle, closing the file when the client leaves mid-body; a HEAD request gets the headers only - `inst-stream`
9. [x] - `p2` - Answer an error as plain text `<code> <status>` with `Cache-Control: no-store`; log a failure on the server's side (open, read) to stderr with the file and the reason, a client that left mid-body excepted - `inst-error`

### Build when needed, then serve

- [x] `p2` - **ID**: `cpt-site-flow-production-build-layout-start`

Temporary: remove once FrontX templates share the UI kit across MFEs and the build fits the default heap. A Node host such as Virtuozzo Application Platform installs the dependencies and runs only `npm start`, with no build phase, on as little as 0.4 of a core and 1 GB; a first start there installs and builds in about 12 to 13 minutes with this workaround, while with Node's default heap the build runs out of memory.

**Actor**: `cpt-site-actor-site-developer`

**Use case**: `cpt-site-usecase-change-screen`

**Success Scenarios**:
- The first `npm start` installs the site when it has no finished install from its current lockfile, builds it, then serves `site/dist/` as `cpt-site-flow-production-build-layout-serve-dist` does; a later start with no input changed and the same origin serves at once.

**Error Scenarios**:
- `PORT` is not an integer from 0 to 65535: the command says so and exits with a failure before installing or building anything.
- `npm run setup` or `npm run build` fails or is stopped by a signal: the command prints which one and why and exits with its failure; a setup leaves no mark and a build that started leaves no stamp, so the next start runs it again; a build refused at its stamp step keeps the last stamp (step 1), as nothing the stamp describes changed.

**Steps**:
1. [x] - `p2` - **IF** started with `--stamp-begin` (the step of `npm run build` after the composition), refuse a `site.config.json` it cannot read or a `PORT` step 2 refuses, keeping the last stamp, then remove `site/.dist-stamp`, so a build that stops midway is never fresh, and write a pending stamp with the origin the build bakes in, by the rule of step 5, and the digest of the input files; **IF** started with `--stamp` (its last step), refuse without a pending stamp or `site/dist/index.html`, and otherwise rename the pending stamp to `site/.dist-stamp`, keeping its time, the build's start; both live outside `site/dist/`, so they are never served; **IF** started with `--setup-done` (the last step of `npm run setup`), write the digest of `site/package-lock.json` into `site/node_modules`; then stop - `inst-stamp`
2. [x] - `p2` - **IF** `PORT` is not an integer from 0 to 65535, exit with a failure - `inst-port`
3. [x] - `p2` - **IF** started with `--no-build` or `START_SKIP_BUILD=1`, go to step 7 - `inst-if-skip`
4. [x] - `p2` - **IF** `site/node_modules` carries no mark of a finished setup, or one from another lockfile, run `npm run setup`, whose `npm ci --include=dev` installs the site's devDependencies (its build tools) under `NODE_ENV=production` too - `inst-setup`
5. [x] - `p2` - **IF** `site/dist/` is not fresh (`cpt-site-algo-production-build-layout-dist-fresh`) for the origin, `SITE_ORIGIN`, else `site.config.json`'s, else `http://localhost:$PORT` with a warning, run `npm run build` with that origin and, when `NODE_OPTIONS` sets no heap (`--max-old-space-size` or `--max_old_space_size`), a heap of 75% of the memory limit, the smaller of `process.constrainedMemory()` and `os.totalmem()` (`os.totalmem()` alone when the constrained reading is 0), and `FRONTX_BUILD_CONCURRENCY=1` unless the environment sets it, as a heap cap, this one or the host's, is per process - `inst-build`
6. [x] - `p2` - Run each `npm` step with its output on the terminal, on POSIX in its own process group, passing SIGINT, SIGTERM and SIGHUP on to the whole group, with SIGKILL to what is left of the group after 10 seconds, also when `npm` has ended first (settling a second later even if unreaped members still answer), at once on a second signal, and when the script itself exits first (a fatal signal the script does not pass on, SIGKILL among them, ends it without that and leaves the group running) (on Windows, where only a console Ctrl+C reaches a handler, ending the process tree with `taskkill`); **IF** it fails, exit with its code, **IF** a signal stopped it, or one was passed on, exit with 128 plus the signal's number, without serving - `inst-run`
7. [x] - `p2` - Serve `site/dist/` (`cpt-site-flow-production-build-layout-serve-dist`) - `inst-serve`

## 3. Processes / Business Logic (CDSL)

### Report a failed screen mount

- [x] `p2` - **ID**: `cpt-site-algo-production-build-layout-report-mount-failure`

**Input**: A `mount_ext` action on the screen domain: its subject and its history intent.

**Output**: The screen mounted and the failure report cleared, or the failure reported and the action still failed.

**Steps**:
1. [x] - `p2` - **TRY** mount the subject through the screen domain's exclusive mount strategy - `inst-try-mount`
2. [x] - `p2` - **CATCH** a failed load or mount: report the subject and the history intent (`replace` and `none` kept, anything else `push`) to the shell layout's failure store and rethrow, so the action still fails - `inst-catch-report`
3. [x] - `p2` - Clear the failure report after a successful mount - `inst-clear-on-success`

### Resolve the remote addresses

- [x] `p2` - **ID**: `cpt-site-algo-production-build-layout-resolve-addresses`

**Input**: The build base, the document's address, a laid-out package's folder name.

**Output**: The aggregate's absolute address; each remote's production `publicPath`.

**Steps**:
1. [x] - `p2` - Join the build base, given a trailing slash, with the aggregate's file name and resolve the result against the document's address - `inst-aggregate-address`
2. [x] - `p2` - Write each remote's production `publicPath` as its folder under `mfe/`, relative to the aggregate, with a trailing slash - `inst-relative-public-path`

### Decide whether the build is fresh

- [x] `p2` - **ID**: `cpt-site-algo-production-build-layout-dist-fresh`

**Input**: `site/dist/`, the stamp `site/.dist-stamp`, the origin the build is for, and the build inputs: every template (a folder with `frontx-template.json`), `site.config.json`, the root `package.json`, `package-lock.json`, `scripts/` and `assets/`, and the whole of `site/`.

**Output**: Whether `site/dist/` can be served without a build.

**Steps**:
1. [x] - `p2` - **IF** `site/dist/index.html` is missing, it is not fresh - `inst-if-no-index`
2. [x] - `p2` - Walk the inputs' files, counting a link below an input as a file without following it, skipping `node_modules`, `dist`, `dist-lib`, `@mf-types`, `coverage`, dot entries and `generated-mfe-manifests.json`, which the build writes, for their newest modification time and a digest of their paths with forward slashes; an unreadable folder counts as changed - `inst-scan`
3. [x] - `p2` - It is fresh when the stamp is a record this script wrote, names the same origin and the same digest (no input file added, deleted or renamed), and no input file is newer than the stamp, the build's start - `inst-compare-stamp`

## 4. States (CDSL)

### No Lifecycle to Model

The layout step and the registration bootstrap run once each and keep no entity with a lifecycle; the failure state the mount handler reports into is specified by the shell layout and navigation feature.

## 5. Definitions of Done

### Self-contained, relative dist layout

- [x] `p2` - **ID**: `cpt-site-dod-production-build-layout-dist-layout`

The system **MUST** lay out every remote the manifest aggregate names under `site/dist/mfe/<package>/` with its `publicPath` relative to the aggregate, **MUST** refuse an unknown manifest id or a missing aggregate before it writes, and **MUST** give the same result on every run.

**Implements**:
- `cpt-site-flow-production-build-layout-lay-out-dist`
- `cpt-site-algo-production-build-layout-resolve-addresses`

**Touches**:
- API: `npm run site:dist`, `npm run build`
- Entities: Screen MFE package

### Mount-independent registration

- [x] `p2` - **ID**: `cpt-site-dod-production-build-layout-mount-independent-bootstrap`

The system **MUST** fetch the manifest aggregate from the build base resolved against the document and register every relative remote address as the aggregate writes it, for the MFE handler to resolve against the document, so one build works at the root of an origin and under any sub-path with no origin or path fixed at build time.

**Implements**:
- `cpt-site-flow-production-build-layout-load-screens`
- `cpt-site-algo-production-build-layout-resolve-addresses`

**Touches**:
- API: `GET ./generated-mfe-manifests.json`, `npm run preview`
- Entities: Screen MFE package, Site config

### Failed mounts reported to the page

- [x] `p2` - **ID**: `cpt-site-dod-production-build-layout-failure-report`

The system **MUST** report every failed load or mount of a screen to the shell layout's failure store with the failed action's history intent while the action still fails, and **MUST** clear the report when a screen mounts.

**Implements**:
- `cpt-site-algo-production-build-layout-report-mount-failure`

**Touches**:
- API: `mount_ext` on the screen domain
- Entities: Screen extension

### The build served as the image serves it

- [x] `p2` - **ID**: `cpt-site-dod-production-build-layout-serve-dist`

The system **MUST** serve `site/dist/` from Node's standard library with the security headers, cache policy, content types and folder handling of `deploy/site/Caddyfile`, **MUST** send each file as it is and leave compression to a CDN or proxy in front, **MUST** never serve a file outside `site/dist/` and any method other than GET and HEAD, and **MUST** refuse to start without a build.

**Implements**:
- `cpt-site-flow-production-build-layout-serve-dist`

**Touches**:
- API: `npm start`, `GET /`, `GET /mfe/<package>/remoteEntry.js`
- Entities: Production build (`site/dist/`)

### A start that builds when needed

- [x] `p2` - **ID**: `cpt-site-dod-production-build-layout-start`

Temporary: remove once FrontX templates share the UI kit across MFEs and the build fits the default heap. The system **MUST** install the site on `npm start` when it has no finished install from its current lockfile, **MUST** build it when the build is missing, for another origin, or older than its inputs, **MUST** serve an up-to-date build without building it again, **MUST** size the build's heap from the memory limit (measured: 1 GB builds at 0.4 of a core, 768 MB does not), and **MUST** serve only when told to skip the build.

**Implements**:
- `cpt-site-flow-production-build-layout-start`
- `cpt-site-algo-production-build-layout-dist-fresh`

**Touches**:
- API: `npm start`, `npm start -- --no-build`, `START_SKIP_BUILD`, `SITE_ORIGIN`, `PORT`, `NODE_OPTIONS`, `FRONTX_BUILD_CONCURRENCY`
- Entities: Production build (`site/dist/`), build stamp (`site/.dist-stamp`, `site/.dist-stamp.pending`), setup mark (`site/node_modules/.frontx-setup`)

## 6. Acceptance Criteria

- [x] `npm run site:dist` copies every aggregated remote without the build leftovers, leaves out a built package the aggregate does not carry, rewrites every `publicPath` to the remote folder, replaces a previous layout and refuses an unknown manifest or a missing aggregate (`scripts/site-dist.test.mjs`).
- [x] The bootstrap resolves the aggregate from the build base against the document, fetches it from there and registers a relative `publicPath` as the aggregate writes it, and an absolute one unchanged (`site/src-app/app/mfe/bootstrap.test.ts`, "production layout addressing").
- [x] The bootstrap registers the four base domains before fetching, throws when the fetch fails and registers schemas, manifest, entries and the host's extensions per package (`bootstrap.test.ts`).
- [x] A failed screen mount is reported with its screen and still fails the action; the report clears once a screen mounts (`bootstrap.test.ts`, "screen load failures").
- [x] `npm run build` followed by `npm run preview` serves every address of DESIGN section 4.5 from `site/dist/`, with the generated discovery files beside the host.
- [x] `npm start` serves the document at `/` and `/?screen=docs`, a folder's index without a trailing slash, hashed assets as immutable and every other file with `no-cache`, decided by the resolved file rather than the raw path, the twins as plain text and the web manifest with its type, the security headers without a `Server` header, both they and the hashed-asset pattern held to `deploy/site/Caddyfile`, every file as it is with one tag and no `Content-Encoding` or `Vary` whatever `Accept-Encoding` asks; it answers 304 to a matching, listed, weak or `*` `If-None-Match`, and to an `If-Modified-Since` at or after the file's time when no `If-None-Match` is sent, answers 500 to a file it cannot open and logs it, sends an empty file with a zero length, closes the file when a client leaves mid-body and keeps answering, refuses a `PORT` outside 0 to 65535; it answers 404 to a missing file and to a named pipe, resolves `/../package.json` and `/%2e%2e/package.json` inside the build root (never a file outside it) and answers 404 to a link that leads out of the build, sends no body to HEAD, answers 405 to POST and refuses to start without a build (`scripts/serve-dist.test.mjs`).
- [x] `npm start` treats the build as stale without `site/dist/index.html`, without a stamp or with one it did not write, for another origin, when an input file is deleted, or when a template, `site.config.json`, the root manifest, lockfile, scripts or assets, or a file of `site/` is newer than the stamp, an input as old as the stamp counting as fresh, and ignores installs, outputs, dot entries and the manifests file the build writes; it runs setup without a mark of a finished setup or with one from another lockfile; it sizes the build's heap to 75% of the smaller of the constrained and the total memory, falls back to the total when the constrained reading is 0 or larger than the total, keeps a heap `NODE_OPTIONS` already sets in either spelling, builds the MFEs one at a time unless the environment sets `FRONTX_BUILD_CONCURRENCY`, records the origin it checks with in the stamp, refuses to close a stamp without a build in progress or without `site/dist/index.html`, and defaults `SITE_ORIGIN` to the local server with a warning only when neither the environment nor `site.config.json` names an origin; `npm run build` opens the stamp after the composition and closes it last, and `npm run setup` marks the install last (`scripts/start.test.mjs`).
- [x] At 0.4 of a core and 1 GB with `NODE_ENV=production`, a clean `npm install && npm start` answers with the site, a restart without changes serves without building, and a start after an MFE edit rebuilds (manual check in a container, 2026-11-06).
