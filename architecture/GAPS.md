# Known Gaps - FrontX Site Repository

What the current shell, routing, tooling and ui-kit releases do not do yet, and what the site does about each. Where an upstream report is drafted for a row, the row names the draft by its file name; drafts are sent only on the owner's approval of each item. The design constraints these gaps impose are stated in [DESIGN.md](DESIGN.md) (section 4.10); a section number in this file names a section of that document. A template's own design states the gaps that touch it in its own words and links here.

## Framework, shell and tooling gaps

None of these removes anything from the scope; each is what the current shell, routing or tooling does not do yet. Ids are stable: the ids missing from the table (G4, G5, G7, G13, G16, G17, G18, G19, G20, G30, G35) are retired; G35 is retired because no screen reads the shell's screen list any more; G17 and G30 are closed by `@gears-frontx/mfes` `0.3.1`, which keeps a styled MFE's mount contract and keeps its stylesheets until its unmount settles, and what the site does about the retired ones is described in section 4.3.4.

## Kit gaps

The pages are composed from `@gears-frontx/ui-kit` components first. Where a kit component fits, the pages and blocks use it directly with no wrapper: `Item` and `ItemGroup` (checklists, file and link lists, each `Item` with `role="listitem"`), `Card`, `Button` and `buttonVariants` (a link drawn as a button is the link element with `buttonVariants`, never `Button` rendered as the link), `Badge`, `Alert`, `Empty`, `Spinner`, `Collapsible`, `Accordion`, `Tabs`, `NavigationMenu`, `Input`, `Chart`. The parts the kit lacks live in three layers, each in one place: the kit candidates of template-kit-candidates (`@gears-frontx/kit-candidates`, the components two proposed kit pull requests add, under the kit's names), the brand of template-site-brand (values over the kit's tokens, and the brand art components), and the blocks of template-site-blocks (and the blocks of template-inbox, template-mfe-demo and template-catalogue), built from the kit, the candidates and the brand with layout-only CSS on tokens. The shell chrome in `site/src-app/app/layout/ui/` follows the block rules, since the shell cannot import from a template. Pages are entries over blocks and carry no CSS. Each visual declaration a block or the shell chrome keeps because the kit lacks something is a row of its exemptions ledger (`styles-exemptions.json`), and the kit gaps those rows wait for are the second table below, one row per gap. The catalogue's list card (a bordered list with a tinted header band, divided rows, meta and arrow) is catalogue-mfe's `ListCard` block, because the kit `Card` pads its content; the catalogue's code frame is the kit-candidate `CodeBlock`. Every piece below is a candidate for design and for the kit:

| Piece | Kit gap it fills |
|---|---|
